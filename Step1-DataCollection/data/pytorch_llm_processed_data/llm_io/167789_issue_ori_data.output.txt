**Title**: [dynamo] sys.setrecursionlimit doesn't seem to do anything

**Issue ID**: 167789

**Bug Description**: The issue describes that when using `torch.compile` with the "eager" backend, setting `sys.setrecursionlimit` to a high value doesn't prevent a RecursionError. Without compilation, the same code works fine. The issue mentions that setting `tstate->c_recursion_remaining` to a high value in C dynamo would fix the problem, suggesting an eval_frame API is needed to modify the C recursion limit.

**Repro Code**: The code is provided in the issue:
```python
import sys
import torch

def fn(x, n):
    if n == 0:
        return x
    return fn(x, n - 1) + 1

@torch.compile(backend="eager")
def outer(x):
    return fn(x, 1000)

sys.setrecursionlimit(10000000)
outer(torch.ones(3))
```
