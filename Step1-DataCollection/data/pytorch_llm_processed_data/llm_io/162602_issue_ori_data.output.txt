**Title**: "torch.argsort can't sort correctly in CUDA when meeting large float"

**Issue ID**: 162602

**Bug Description**: The issue describes a bug where `torch.argsort` produces different results on CPU vs CUDA when sorting a tensor containing large float values.

**Repro Code**:
```python
DEVICE = 'cpu'
device = DEVICE
import torch
torch.manual_seed(42)
torch.cuda.manual_seed(42)
input_tensor = torch.tensor([1e+39, 1e+308, 1.0, 2.5, -3.7, 0.0], device=device)
dim = 0
descending = False
stable = False
result = torch.argsort(input_tensor, dim=dim, descending=descending, stable=stable)
print(result)
```

**Repro Output**:
- CPU output: `tensor([4, 5, 2, 3, 0, 1])`
- CUDA output: `tensor([4, 5, 2, 3, 1, 0], device='cuda:0')`

The difference is in the last two elements - CPU has `[0, 1]` while CUDA has `[1, 0]`.

**Trigger Conditions**:
- Backend: CUDA (the bug only occurs on CUDA, not CPU)
- dtype: The tensor contains float values (likely float32 or float64 based on the large values like 1e+308)
- input_shape: 1D tensor with 6 elements
- other_conditions: Large float values (1e+39, 1e+308) in the input tensor

**Affected API**: `torch.argsort`

**Environment**:
- PyTorch version: 2.6.0+cu124
- Python version: 3.10.17
- OS: Ubuntu 24.04.2 LTS (x86_64)


- Hardware: NVIDIA A800 80GB PCIe
