**Title**: AOTAutograd view replay crashes when an intermediate aliased base becomes non-contiguous after Inductor padding

**Issue ID**: 163328

**Bug Description**: 
Under `torch.compile(backend="inductor", mode="reduce-overhead", fullgraph=True)`, AOTAutograd's runtime view-replay for aliased outputs crashes with:
```
RuntimeError: view size is not compatible with input tensor's size and stride (at least one dimension spans across two contiguous subspaces). Use .reshape(...) instead.
```

Root cause: An intermediate base tensor (internally marked is_output but not user-visible) gets padded by Inductor, making it non-contiguous at runtime. AOTAutograd later tries to replay recorded view metas off this base and hits a stride/size compatibility error.

**Repro Code**: Provided in the issue

**Repro Output**: The error message mentioned above

**Trigger Conditions**:
- backend: "inductor"
- mode: "reduce-overhead"
- fullgraph: True
- The intermediate base is marked is_output internally but is not a user-visible output (hence eligible for padding/realignment)
- There are two (or more) outputs that are views (e.g., reshape) of this same base
- With view_replay_for_aliased_outputs=True (default), _functionalize_apply_view_metas attempts replay on the padded base and fails

**Affected API**: 
- torch.compile
- AOTAutograd view replay (_functionalize_apply_view_metas)
- torch.cat (mentioned as incidental)
- reshape

**Environment**:
- PyTorch version: 2.4.1+cu121, also reproduces on 2.6.0
- Python version: 3.8.17, also reproduces on 3.10


- OS: unknown
- Hardware: CUDA (device="cuda")
