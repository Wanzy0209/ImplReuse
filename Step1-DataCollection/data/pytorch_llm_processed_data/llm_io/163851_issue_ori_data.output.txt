**Title**: [MPS] Unexpected output forgrid_sampler_3dwhen grid hasnanvalue

**Issue ID**: 163851

**Bug Description**: The issue describes a bug where `torch.grid_sampler_3d` produces different outputs on CPU vs MPS when the grid contains NaN values. On CPU, the output correctly contains NaN values, but on MPS, the NaN values are replaced with 1. The issue mentions that in the Metal kernel, the `nan` value is set to be -1.

**Repro Code**:
```python
import torch

input = torch.ones(1,1,3,3,3)
grid_nan = torch.tensor([[[[[torch.nan, 1., 1.],[1., 1., 1.]]]]])

out_cpu = torch.grid_sampler_3d(input, grid_nan, 0, 0, True)
out_mps = torch.grid_sampler_3d(input.to("mps"), grid_nan.to("mps"), 0, 0, True)
print("CPU:", out_cpu.flatten()) # tensor([nan, 1.])
print("MPS:", out_mps.flatten()) # tensor([1., 1.], device='mps:0')
```
