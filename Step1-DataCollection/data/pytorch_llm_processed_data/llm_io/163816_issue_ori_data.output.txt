**Title**: baddbmm with out_dtype=torch.float32 does not validate batch broadcast, silently gives incorrect result

**Issue ID**: 163816

**Bug Description**: The issue describes a bug where `torch.baddbmm` behaves differently when `out_dtype=torch.float32` is specified. Without this parameter, it correctly raises a validation error when batch dimensions don't match. With `out_dtype=torch.float32`, it silently produces an incorrect output shape instead of validating or broadcasting properly.

**Repro Code**: The issue provides two code snippets - one that works correctly (raises error) and one that exhibits the bug. The buggy version is:

```python
device=torch.device('cuda')
in_features = 80
out_features = 128
dtype=torch.bfloat16
weight = torch.zeros(out_features, in_features, dtype=dtype, device=device)
bias = torch.zeros(out_features, dtype=dtype, device=device)
input = torch.zeros(2, 64, in_features, dtype=dtype, device=device)
print(torch.baddbmm(
    input=bias.view(1, 1, out_features),
    batch1=input,
    batch2=weight.mT.unsqueeze(0),
    out_dtype=torch.float32,
).shape)
```

**Repro Output**: `torch.Size([1, 1, 128])` (incorrect, expected either `[2, 1, 128]` if broadcast is supported, or a validation error)

**Trigger Conditions**:
- Backend: CUDA
- dtype: bfloat16 (input), float32 (output via out_dtype)
- input_shape: batch1 has shape [2, 64, 80], batch2 has shape [1, 80, 128], input (bias) has shape [1, 1, 128]


- other_conditions: The bug occurs specifically when `out_dtype=torch.float32` is specified and batch dimensions don't match

**Affected API**: `torch.baddbmm`

**Environment**:
- pytorch_version: 2.8.0
- python_version: 3.10.12
- os: Ubuntu 22.04.5 LTS (x86_64)
- hardware: NVIDIA H100 80GB HBM3 (CUDA available)
