Summary
A buffer overflow vulnerability in torch.nn.utils.rnn.pad_packed_sequence (https://github.com/advisories/GHSA-f4hp-rmr7-r7v8) allows local attackers to corrupt memory by manipulating the function’s internal state. This issue affects several PyTorch versions (including 2.8.0) and is rated High severity.

Details
The flaw occurs in nn/utils/rnn.py, where invalid PackedSequence metadata can cause out-of-bounds writes during padding. It is exploitable only locally but can crash the process or enable limited memory corruption.
Affected dependencies include:
unstructured@0.18.14, effdet@0.4.1, torchvision@0.23.0, timm@1.0.15, accelerate@1.9.0, and unstructured-inference@1.0.5, all introducing torch@2.8.0.

PoC
A crafted PackedSequence with inconsistent batch_sizes or sequence lengths triggers the overflow when passed to pad_packed_sequence.
Test only in isolated environments.

Impact
Type: Buffer overflow / memory corruption
Scope: Local execution required
Impact: Possible crash or memory corruption
Affected: All environments using vulnerable torch versions, directly or through dependencies
