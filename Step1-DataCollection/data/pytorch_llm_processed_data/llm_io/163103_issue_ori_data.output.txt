**Title**: [lr_scheduler] Multiple LR schedulers incorrectly alias self._last_lr/get_last_lr(...) with group["lr"] when using tensor lr

**Issue ID**: 163103

**Bug Description**: The issue describes that several LR scheduler components (`LRScheduler._update_lr`, `ChainedScheduler.__init__`, `ChainedScheduler.step`, `ReduceLROnPlateau.__init__`, `ReduceLROnPlateau.step`, and `CosineAnnealingWarmRestarts.step`) incorrectly alias `self._last_lr`/`get_last_lr(...)` with `group["lr"]` when `group["lr"]` is a tensor. This happens with patterns like:
```python
self._last_lr: list[float] = [group["lr"] for group in self.optimizer.param_groups]
```

This leads to unintended lr corruption and violates type annotations (which mark `_last_lr` and `get_last_lr(...)` as `list[float]`).
