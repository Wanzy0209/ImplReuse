Bug Report:
Title: Stable headers shouldn't use anonymous namespaces
Issue ID: 163343
Original bug description: ### 🐛 Describe the bug

Some of the headers of the stable API have anonymous namespaces inside of them:
https://github.com/pytorch/pytorch/blob/264e7f68a095b5b2f10e7ca66a3bbb16f6e56e28/torch/csrc/stable/stableivalue_conversions.h#L11-L13

This is considered an [anti-pattern](https://clang.llvm.org/extra/clang-tidy/checks/misc/use-anonymous-namespace.html), and it has the side effect that the global `to` and `from` names are overloaded in every file that includes those headers.

I'm not sure whether I fully grasp the original reason for using an anonymous namespace, but I wonder whether an anonymous namespace _inside_ a named namespace would work. Something like this:
```cpp
namespace torch::stable {
namespace {
template <typename T>
StableIValue from(T val);
template <typename T>
T to(StableIValue val);
}
}
```
