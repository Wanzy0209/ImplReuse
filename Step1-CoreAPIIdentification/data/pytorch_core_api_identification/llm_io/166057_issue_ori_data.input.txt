Title: [RISC-V][RVV][GCC 14.2] GCC ICE when building DepthwiseConvKernel.cpp
Issue ID: 166057
Original bug description: ### 🐛 Describe the bug

## Description

While building PyTorch for RISC‑V with RVV enabled (`-march=rv64gcv`), GCC 14.2 hits an internal compiler error (ICE) when compiling `aten/src/ATen/native/cpu/DepthwiseConvKernel.cpp`. The crash is triggered by statements that use an RVV intrinsic `__riscv_vset_v_f32m1_f32m1x4` to write results directly back to a dereferenced pointer in the same expression, effectively doing read-modify-write on the same `MEM_REF`.

Refactoring these sites to first load into a temporary vector, perform `vset` operations on the temporary, and then write back once, avoids the ICE. Clang does not reproduce the issue; it compiles the original code fine (See https://github.com/pytorch/pytorch/pull/127867).

## Affected file and code sites (current main)

- Patterns like the following in `DepthwiseConvKernel.cpp` trigger the ICE:
``` c
*transform = __riscv_vset_v_f32m1_f32m1x4(*transform, 0, g0);
*transform = __riscv_vset_v_f32m1_f32m1x4(*transform, 1, vmuladdq_f32(half_g0_plus_g2, const_half, g1));
*transform = __riscv_vset_v_f32m1_f32m1x4(*transform, 2, vmulsubq_f32(half_g0_plus_g2, const_half, g1));
*transform = __riscv_vset_v_f32m1_f32m1x4(*transform, 3, g2);
```
