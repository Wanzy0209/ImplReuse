Bug Report:
Title: PyTorch's atan2 function avoids computational anomalies when the input is zero, but the backward gradient becomes NaN.
Issue ID: 165427
Original bug description: ### 🐛 Describe the bug

When my model encountered corrupted data, both inputs to PyTorch's `atan2` function became zero. During the forward pass, `atan2` successfully avoided a division-by-zero issue, but during backpropagation, the gradients became NaN. My suggestion is: could we either ensure that both the forward and backward passes gracefully handle the case where both inputs are zero, or alternatively, add an assertion to explicitly disallow both inputs being zero?

### Versions

2.4.0
