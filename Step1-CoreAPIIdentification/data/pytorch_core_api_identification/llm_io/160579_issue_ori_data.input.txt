Bug Report:
Title: [ROCm] tools/amd_build/build_amd.py is not idempotent (keeps modifying torch/csrc/cuda/Module.cpp)
Issue ID: 160579
Original bug description: ### 🐛 Describe the bug

I noticed this since I'm writing some build scripts for ROCm on Windows support and I'm running these scripts locally multiple times.

Each time I run `python .\tools\amd_build\build_amd.py` (script source here: https://github.com/pytorch/pytorch/blob/main/tools/amd_build/build_amd.py), an extra `hip/` is prepended to `driver_types.h` here: https://github.com/pytorch/pytorch/blob/d1950d4bb5cba8fb6b23e4d283eea5b9801737e2/torch/csrc/cuda/Module.cpp#L1045

The initial diff there is:
```diff
auto m = py::handle(module).cast<py::module>();
-// CUuuid is defined in either cuda.h or driver_types.h
+// hipUUID is defined in either cuda.h or hip/driver_types.h
// hipified to hipUUID which is defined in hip_runtime_api.h
```

Running `build_amd.py` again, I get:
```diff
   auto m = py::handle(module).cast<py::module>();
-  // hipUUID is defined in either cuda.h or hip/driver_types.h
+  // hipUUID is defined in either cuda.h or hip/hip/driver_types.h
   // hipified to hipUUID which is defined in hip_runtime_api.h
```

Then I can keep running the script with an extra `hip/` added each time, e.g.
```
// hipUUID is defined in either cuda.h or hip/hip/hip/hip/hip/hip/hip/driver_types.h
```

That is the only file that continues to be changed on a re-run.

### Versions

I'm based off of https://github.com/pytorch/pytorch/commit/3cec82a7e9aea040a34dd7a2587ae6d3bd65dba0 (recent as of yesterday)
