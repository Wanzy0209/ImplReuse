Bug Report:
Title: torch.export converts all operator arguments to positional, losing parameter names - impacts MLIR lowering
Issue ID: 166851
Original bug description: ### 🚀 The feature, motivation and pitch

Description
When exporting models using torch.export.export(), both built-in PyTorch operators and custom operators have their keyword arguments automatically converted to positional arguments in the exported graph. This results in the loss of parameter name information, which is critical for:
1. MLIR lowering: MLIR dialects rely on named attributes to correctly map operations
2. Semantic preservation: Parameter names provide essential semantic meaning that is lost with positional-only representation

Expected Behavior
Operators with named parameters should preserve those names as keyword arguments in the exported graph, enabling downstream tools to understand the semantic meaning of each parameter.
