Bug Report:
Title: _scaled_mmerrors and_int_mmis slow with row-major rhs matrix
Issue ID: 164491
Original bug description: ### 🐛 Describe the bug

I'm not sure if this is considered an issue by the torch team, since `_int_mm` and `_scaled_mm` are not part of a stable and documented API. If not, feel free to close it.

_scaled_mm raises an error if the rhs matrix is row-major. _int_mm does not, but it is very slow in benchmarks. Presumably, it does a transparent rhs.T.contiguous().T before applying the mm.

both column-major and row-major rhs matrices are common use cases, because your weights matrix in a Linear layer is transposed for your forward pass and not transposed for your backward. So either one of those will be row-major, no matter how you store it.

Attached you can find a Triton kernel that we are using instead for this case. It's not as optimized as torch kernels, but due to its strided access to the matrix it is much faster than convert the matrix to column-major first.

[triton_mm_8bit(3).py](https://github.com/user-attachments/files/22665283/triton_mm_8bit.3.py)
