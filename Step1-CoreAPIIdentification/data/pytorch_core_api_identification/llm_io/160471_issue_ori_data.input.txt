Bug Report:
Title: [dynamo] Instruction starts_line gets removed incorrectly
Issue ID: 160471
Original bug description: ### 🐛 Describe the bug

I'm running into an issue ([internally](https://fb.workplace.com/groups/1028545332188949/permalink/1283920796651400/)) where metadata attached to an fx.GraphModule that is being retraced with TorchDynamo is not being propagated to the output graph of TorchDynamo.

The metadata is propagated by [this piece of code](https://github.com/pytorch/pytorch/blob/b4596895b9d85a686c2cb978938b0a7797b3690a/torch/_dynamo/output_graph.py#L2432-L2452), where previously we've created a mapping of line numbers to metadata, and based on the instruction's start line, we look up the metadata mapping. However, in the internal issue above, the start line for the instructions are all somehow set to one line, line 197. 

Looking at the `dis.dis(gm.forward.__code__)`, the instructions look something like:
```
trainer/0 [0]:197         10216 LOAD_FAST                0 (self)
trainer/0 [0]:            10218 LOAD_ATTR                8 (depth_decoder)
...
trainer/0 [0]:198         10262 EXTENDED_ARG             1
trainer/0 [0]:            10264 LOAD_GLOBAL            302 (torch)
...
trainer/0 [0]:199         10420 EXTENDED_ARG             1
trainer/0 [0]:            10422 LOAD_GLOBAL            302 (torch)
```
After line 197, the line numbers only appear on `EXTENDED_ARG` opcodes. However the [strip_extended_args](https://github.com/pytorch/pytorch/blob/b4596895b9d85a686c2cb978938b0a7797b3690a/torch/_dynamo/bytecode_transformation.py#L1569) function removes all the lines with `EXTENDED_ARG` opcode, resulting in none of the lines having a line number after line 197.
