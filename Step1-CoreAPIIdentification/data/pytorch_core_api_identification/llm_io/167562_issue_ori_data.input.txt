Bug Report:
Title: Passing a scalar torch.Tensor to an IntList is completely broken
Issue ID: 167562
Original bug description: ### 🐛 Describe the bug

PythonArgParser accepts a scalar Tensor in places that expect an `IntList`. However, the parsing code casts the Tensor to a PyListObject. It just so happens that PyListObject `ob_size` is the same place as THPVariable's `bool isBorrowed_` from `MaybeOwned<Tensor>` so the parsing code thinks it's an empty list (!?) but none of this makes any sense.

For example, in eager mode:

```python
    x = torch.ones(1, 2, 3, 4, 5)
    print(x.sum(dim=torch.tensor(3)))  # Ed, why are we accepting a scalar tensor here?!
    print(x.sum(dim=3))
```

It also shows up in places where we generate scalar FakeTensors, such as `random.randint()`:

```python
import torch
import random

def foo():
    x = torch.ones(2, 2, 2)
    return x.sum(dim=random.randint(0, 0))  # i.e.,  dim=0

@torch.compile
def foo_compile():
    x = torch.ones(2, 2, 2)
    return x.sum(dim=random.randint(0, 0))  # i.e.,  dim=0

assert foo().shape == foo_compile().shape
```
