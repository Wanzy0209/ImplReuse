Bug Report:
Title: [MPS]torch.compileResNet-18 model fails duringloss.backward()on MPS backend, but works on CPU
Issue ID: 161905
Original bug description: ### 🐛 Describe the bug

#### 🐛 Bug

When using `torch.compile` on a model that has been moved to the `mps` device on macOS, calling `loss.backward()` results in a runtime error. The forward pass completes without issues.

Notably, the exact same code runs successfully without any errors when the model and data are on the `cpu` backend. This suggests a potential bug or unimplemented feature in the `torch.compile` support for the MPS backend, specifically concerning the backward pass (gradient computation).

#### To Reproduce

Here is a minimal, self-contained code snippet to reproduce the error:

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch import Tensor
from typing import Type, Any, Callable, Union, List, Optional
from torchvision.models.resnet import resnet18


BATCH_SIZE = 4
NUM_CLASSES = 10
LEARNING_RATE = 0.01
device='mps'

model = resnet18(num_classes=NUM_CLASSES)

criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=LEARNING_RATE)

model=model.to(device)
model.train() 

@torch.compile
def train(images,labels):
    images=images.to(device)
    labels=labels.to(device)
    
    optimizer.zero_grad()

    outputs = model(images)
    loss = criterion(outputs, labels)
    loss.backward()
    optimizer.step()

images = torch.randn(BATCH_SIZE, 3, 224, 224)
labels = torch.randint(0, NUM_CLASSES, (BATCH_SIZE,))

train(images,labels)
```

#### Expected behavior

The code should execute without any errors, regardless of whether the `DEVICE` is set to `'mps'` or `'cpu'`. The `loss.backward()` call should complete successfully, and the gradients for the model's parameters should be computed.

#### Actual behavior

When `DEVICE = 'mps'`, the code fails at `loss.backward()` with a runtime error. The forward pass and loss calculation are successful.
