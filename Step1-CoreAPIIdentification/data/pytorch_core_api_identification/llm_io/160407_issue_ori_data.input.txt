Bug Report:
Title: Bilinearmodule can't be made lazy due to new checks introduced in__init__
Issue ID: 160407
Original bug description: ### 🐛 Describe the bug

https://github.com/pytorch/pytorch/pull/149018 introduced a check in the `__init__` function of the bilinear layer to resolve https://github.com/pytorch/pytorch/issues/103425.

However, I think there is a good use case to set the values `in1_features` and `in2_features` to 0, which is if someone wants to create a `LazyBilinear` module 

https://gist.github.com/Rathur421/7bc45de9e982651b27d2382c2464284b.

This will currently raise an error due to the introduced check (i.e.):

```python
        if in1_features <= 0:
            raise ValueError(f"in1_features must be > 0, but got {in1_features}")
```
One possible solution is to move the check just before it meets the possible division per 0 in the [`reset_parameters`](https://github.com/pytorch/pytorch/blob/ba56102387ef21a3b04b357e5b183d48f0afefc7/torch/nn/modules/linear.py#L220) function so that it looks like the following.
```python
    def reset_parameters(self) -> None:
        if self.in1_features <= 0:
            raise ValueError(f"in1_features must be > 0, but got {self.in1_features}")
        bound = 1 / math.sqrt(self.weight.size(1))
        init.uniform_(self.weight, -bound, bound)
        if self.bias is not None:
            init.uniform_(self.bias, -bound, bound)
```

Let me know what you think of it. I should be able to find some time to make a pr in the following days.

If you think a `LazyBilinear` module could be a good addition please let me know as well.
