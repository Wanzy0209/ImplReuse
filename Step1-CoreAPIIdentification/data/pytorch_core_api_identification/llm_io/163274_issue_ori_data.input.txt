Bug Report:
Title: [DLPack] Further restrict the normalization condition for DLPack Export
Issue ID: 163274
Original bug description: Previously in https://github.com/pytorch/pytorch/issues/83069,https://github.com/pytorch/pytorch/pull/83158, we decided to normalize the DLPack tensor if the tensor's shape[i] equals 1, however. Such normalization can cause issue for down stream consumers. Specifically, say a column major tensor

```python
shape=(1024, 1), stride=(1, 1024)
```

Exporting this tensor will trigger normalization, and as a result stride becomes `stride=(1, 1)`, because it is non-contiguous, and there is opportunity to do so. While it is not wrong(as a matter of fact, any `stride=(1, x)` is valid),  `stride=(1, 1)` is usually harder to handle for many cases, on one thing, it is harder to detect for example the tensor is in column major. Stride settings in cases like GPU tma also do not like such duplicated strides.

Reading the original post, seems the original intention is to enable the use-case of single dimension array`shape=(1,)`, `stride=(x,)` and normalize that to  `stride=(1,)`. Which could make sense. While the multi dimensional normalization can be counter productive.

As a result, we think ideally to restrict normalization to one dimension array, it will also further speedup the conversion
