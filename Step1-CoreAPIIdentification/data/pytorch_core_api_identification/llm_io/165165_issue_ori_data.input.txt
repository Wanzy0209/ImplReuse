Bug Report:
Title: Proposal to bring back 12.9 wheels
Issue ID: 165165
Original bug description: This is a request coming from vLLM to bring back 12.9 nightly and release wheels for performance reason because the core workload of vLLM needs to run DeepGEMM which only get good performance with 12.9.  This is documented on https://github.com/deepseek-ai/DeepGEMM?tab=readme-ov-file#requirements.

As this is in conflict with PyTorch's current plan to maintain 3 CUDA versions (12.6, 12.8, 13.0) with 12.8 is the default one.  I want to put some discussion points here:

1. Do we need to bring back 12.9 nightlies? Probably yes.  There is already a PR to do this for PyTorch https://github.com/pytorch/pytorch/pull/163029#pullrequestreview-3226756600, but there wasn't enough incentive to do that until now
2. Do we need to build vision and audio 12.9 (and maybe torchao)? Yes, they are all used in vLLM
3. Even if 12.9 can come back, we need an agreement on when to remove it:
    1. When 13.0 becomes the main CUDA version in OSS
    2. @zou3519 also proposes that we could do that when fbcode gets 13.0.  In any case, 13.0 is not well tested at the moment so it will still be a long way from now
4. Do we need vLLM perf comparison between 12.8 vs 12.9 to support the claim from https://github.com/deepseek-ai/DeepGEMM?tab=readme-ov-file#requirements.  We don't have that data point at the moment

cc @seemethere @malfet @pytorch/pytorch-dev-infra @atalman @zou3519 @simon-mo
