Bug Report:
Title: check_binary tests not catching AArch64+CPU openBLAS dependency missing
Issue ID: 168000
Original bug description: ### 🐛 Describe the bug

https://github.com/pytorch/pytorch/pull/166044 was recently merged and all AArch64 CPU builds and checks passed, however there we're some problems with the resulting binary

openblas library not linked when expected to ( Fixed in https://github.com/pytorch/pytorch/pull/166044 )

EDIT

I think that the reason is because the dependency exists on system so the linker is able to link it correctly, except it is not packaged into the whl and rpath set. 

I think the same problem would happen if arm_compute.so was missing from the DEPS_LIST.

TLDR; It seems we test the binaries in the same docker image that we build them, despite the fact that some of the dependencies are copied straight from the docker image into the whl. Therefore the test does not correctly check that those packaged library files are the ones being linked to.

See https://github.com/pytorch/pytorch/actions/runs/19421948119/job/55577154540

libgomp has the correct linker path, but libarm_compute.so, libgfortran.so and libopenblas.so are all linking to system so files, not the ones installed in torch lib.
