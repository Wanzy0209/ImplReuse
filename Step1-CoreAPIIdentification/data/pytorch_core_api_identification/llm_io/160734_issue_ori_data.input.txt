Bug Report:
Title: MPS clamp operation does not fully support broadcasting
Issue ID: 160734
Original bug description: ### 🕵️‍♂️ Detected with [FACTO](https://github.com/meta-pytorch/FACTO)

### 🐛 Describe the bug

The CPU clamp operation fully supports broadcasting between the input and the min/max tensors. However MPS fails when the number of dimensions of min or max is greater than that of input tensor

```python
import torch

def test_clamp(device):
    x = torch.randn(2, 3, device=device)
    min_t = torch.randn(1, 2, 3, dtype=x.dtype, device=device)
    max_t = torch.randn(1, 2, 3, dtype=x.dtype, device=device)
    try:
        torch.clamp(x, min=min_t, max=max_t)
        print(f"clamp test succeeds for device: {device}")
    except RuntimeError as e:
        print(f"clamp test fails for device: {device}: {e}")

test_clamp(device = "cpu")
test_clamp(device = "mps")
```

terminal output:
```
clamp test succeeds for device: cpu
clamp test fails for device: mps: impl: clamp tensor number of dims must not be greater than that of input tensor
```
