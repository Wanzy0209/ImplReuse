Bug Report:
Title: CUDA not available on WSL with custom-built PyTorch for Blackwell architecture (Compute Capability 12.0)
Issue ID: 162403
Original bug description: ### 🐛 Describe the bug

System Information

    PyTorch Version: 2.9.0a0+git32911ff (and various other nightly builds)

    OS: Windows 11 Enterprise (Build 26100) with WSL 2 (Ubuntu)

    Python Version: 3.11.13

    GPU: NVIDIA GeForce RTX 5060 Ti (Blackwell Architecture, Compute Capability 12.0)

    NVIDIA Driver Version (Windows): 581.15

    CUDA Version (reported by nvidia-smi in WSL): 13.0

    How PyTorch was installed: Compiled from the master branch of the official PyTorch repository on 2025-09-08.

Problem Description

Despite a successful, clean compilation of PyTorch from the latest source code specifically targeting the Blackwell architecture (TORCH_CUDA_ARCH_LIST="12.0"), the resulting PyTorch installation fails to detect the CUDA-enabled GPU within the WSL environment. The function torch.cuda.is_available() consistently returns False.

This occurs even though nvidia-smi works perfectly within the same WSL session, correctly identifying the GPU, driver, and CUDA version. The issue seems to be a failure in the final API link between the custom-built PyTorch and the CUDA libraries exposed by the WSL driver, pointing towards a potential bug in either the PyTorch build process for this new architecture or the NVIDIA driver's interaction with WSL.

### Error logs

Steps to Reproduce

The environment was set up following a meticulous, multi-step process that ruled out common configuration errors. The final, successful compilation process was as follows:

    System Setup: A clean WSL (Ubuntu) environment with build-essential, cmake, git, and ninja-build installed.

    Python Environment: A clean Python 3.11 virtual environment was created (venv). pip, setuptools, wheel, and other build dependencies (sympy, numpy, pyyaml, etc.) were installed and updated.

    PyTorch Source: The latest master branch of pytorch/pytorch was cloned recursively.

    Build Configuration: The build was configured with the following environment variables to target the Blackwell GPU specifically:

    export TORCH_CUDA_ARCH_LIST="12.0"
    export USE_NINJA=1

    Compilation: PyTorch was built and installed using python setup.py install. The compilation process completed successfully without any errors.

    Verification: A Python script was run to check for CUDA availability. The key check fails:

    import torch
    # This line returns False
    print(torch.cuda.is_available())

    Troubleshooting: The LD_LIBRARY_PATH was explicitly and dynamically set to the directory containing libcuda.so.1 (/usr/lib/wsl/lib) before running the verification script, but this did not resolve the issue.

### Versions

Expected Behavior

Given that nvidia-smi functions correctly and PyTorch was compiled from source for the target architecture, torch.cuda.is_available() is expected to return True.
Actual Behavior

torch.cuda.is_available() returns False. The verification script fails with the error: AssertionError: ¡FALLO CRÍTICO! CUDA no está disponible. (Critical failure! CUDA is not available).
