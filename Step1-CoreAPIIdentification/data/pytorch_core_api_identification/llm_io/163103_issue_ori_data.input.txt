Bug Report:
Title: [lr_scheduler] Multiple LR schedulers incorrectly alias self._last_lr/get_last_lr(...) with group["lr"] when using tensor lr
Issue ID: 163103
Original bug description: ### 🐛 Describe the bug

`LRScheduler._update_lr`, `ChainedScheduler.__init__`, `ChainedScheduler.step`, `ReduceLROnPlateau.__init__`, `ReduceLROnPlateau.step`, and `CosineAnnealingWarmRestarts.step` alias `self._last_lr`/`get_last_lr(...)` with `group["lr"]` when `group["lr"]` is a tensor with patterns like this:
```python
self._last_lr: list[float] = [group["lr"] for group in self.optimizer.param_groups]
```

This can lead to unintended lr corruption and violates type annotations (which currently mark `_last_lr` and `get_last_lr(...)` as `list[float]`.
