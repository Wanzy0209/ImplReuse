Bug Report:
Title: baddbmm with out_dtype=torch.float32 does not validate batch broadcast, silently gives incorrect result
Issue ID: 163816
Original bug description: ### 🐛 Describe the bug

first, a known-good baseline: we do a baddbmm where the input tensor has batch 2 but the weight and bias have batch 1.  
baddbmm() rejects this and tells me to ensure the batch dims match:

```python
device=torch.device('cuda')
in_features = 80
out_features = 128
dtype=torch.bfloat16
weight = torch.zeros(out_features, in_features, dtype=dtype, device=device)
bias = torch.zeros(out_features, dtype=dtype, device=device)
input = torch.zeros(2, 64, in_features, dtype=dtype, device=device)
print(torch.baddbmm(
    input=bias.view(1, 1, out_features),
    batch1=input,
    batch2=weight.mT.unsqueeze(0),
).shape)
Traceback (most recent call last):
  File "<string>", line 8, in <module>
RuntimeError: Expected size for first two dimensions of batch2 tensor to be: [2, 80] but got: [1, 80].
```

this is _annoying_ (why not just broadcast it for me? the [docs](https://docs.pytorch.org/docs/stable/generated/torch.baddbmm.html) say an input broadcastable with the weights is supported), but whatever, nothing catastrophic.

but now we try the same example with just one change:

```diff
  device=torch.device('cuda')
  in_features = 80
  out_features = 128
  dtype=torch.bfloat16
  weight = torch.zeros(out_features, in_features, dtype=dtype, device=device)
  bias = torch.zeros(out_features, dtype=dtype, device=device)
  input = torch.zeros(2, 64, in_features, dtype=dtype, device=device)
  print(torch.baddbmm(
      input=bias.view(1, 1, out_features),
      batch1=input,
      batch2=weight.mT.unsqueeze(0),
+     out_dtype=torch.float32,
  ).shape)
```

and instead of a validation error like above, or a correct broadcast as I'd prefer: it outputs the wrong shape entirely:

```
torch.Size([1, 1, 128])
```

we're expecting either `([2, 1, 128])` (if broadcast is supported) or a validation error, so a batch dim of 1 is surprising.
