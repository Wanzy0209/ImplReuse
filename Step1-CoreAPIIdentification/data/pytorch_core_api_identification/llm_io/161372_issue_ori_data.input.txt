Bug Report:
Title: torch.compile regression in 2.8.0
Issue ID: 161372
Original bug description: ### 🐛 Describe the bug

Hi there,
I've been a fan of `torch.compile` as it helped to speed up my code substantially in most cases. However, some of it broke in 2.8.0. 

For instance, I have this pure PyTorch implementation of an LLM that is geared towards code readability, which got an ~2x speed-up on CPU and ~4x speed-up on GPU when compiled in PyTorch 2.6 and 2.7.1

<img width="936" height="592" alt="Image" src="https://github.com/user-attachments/assets/5d8954c1-1624-456b-ad02-16588aa37eef" />

Now, in 2.8.0, this no longer works as the compilations errors with:

```python

  r = torch.where(mask, value, a)  # type: ignore[arg-type]

W0823 18:56:31.554000 40177 torch/_dynamo/convert_frame.py:1016] [0/8]    function: 'forward' (/Users/sebastian/Desktop/qwen3.py:57)
W0823 18:56:31.554000 40177 torch/_dynamo/convert_frame.py:1016] [0/8]    last reason: 0/7: tensor 'cache.cache[0][0]' size mismatch at index 2. expected 77, actual 78
```

Sure, the code is not particularly optimized for compilation (like I mentioned above, it's geared towards readability for educational purposes and hackability), but it did work fine in 2.6 and 2.7.1, which is why I think this is a regression.
