Bug Report:
Title: Bug: Incorrect dependency length calculation fornode2inscore_fusion_memory
Issue ID: 165724
Original bug description: ### 🐛 Describe the bug

There is a copy-paste error in the `score_fusion_memory` method when calculating the total number of dependencies for `node2`. The variable `node2_dep_len` is computed using `node1.read_writes.reads` instead of `node2.read_writes.reads`.

https://github.com/pytorch/pytorch/blob/0fabc3ba44823f257e70ce397d989c8de5e362c1/torch/_inductor/scheduler.py#L4472

This bug can cause the subsequent optimization logic to fail. The optimization attempts to identify the node with the smaller dependency set to iterate over, but because `node2_dep_len` may be calculated incorrectly, this optimization may not trigger when it should, potentially leading to degraded performance in the fusion scoring process.
