Bug Report:
Title: torch.compilefails on direct assignment from tuple slice oflinalg_qrresult, while tuple unpacking works
Issue ID: 163253
Original bug description: ### 🐛 Describe the bug

When using `torch.compile`, directly assigning a tuple slice of `torch.linalg.qr` result to a variable (e.g., `U = torch.linalg.qr(x)[:1]`) fails with a `TypeError`. However, using tuple unpacking for the same operation (e.g., `U, = torch.linalg.qr(x)[:1]`) succeeds. Both forms execute correctly in eager mode.
Compilation fails across all torch.compile backends (eager/aot_eager/inductor) with:
```
torch.return_types.linalg_qr() takes a 2-sequence (1-sequence given)
```
### To reproduce
```python
import torch
import torch.nn as nn

class TestModel(nn.Module):
    def forward(self, x):
        # This fails under torch.compile
        Q = torch.linalg.qr(x)[:1]  # Fails: Direct assignment
        # Q, = torch.linalg.qr(x)[:1]  # Works: Tuple unpacking
        return Q

x = torch.randn(4, 4)
model = TestModel()

print("Eager output:", model(x))
print("Compiled output:", torch.compile(model)(x))
```
