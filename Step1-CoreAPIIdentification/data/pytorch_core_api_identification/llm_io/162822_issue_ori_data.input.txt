Bug Report:
Title: Pipeline parallelism does not correctly initialize backwards stages when evaluating before training.
Issue ID: 162822
Original bug description: ### 🐛 Describe the bug

When running evaluation with [pipeline parallelism schedules](https://github.com/pytorch/pytorch/blob/release/2.9/torch/distributed/pipelining/schedules.py) before training, the following happens:

- Calling [eval()](https://github.com/pytorch/pytorch/blob/152383b74540785da418611a8ae8a7c5028a0cdc/torch/distributed/pipelining/schedules.py#L385) on any of the schedules, it will temporary set _has_backwards to False, before performing a step().
- The step() will then initialize the [stage](https://github.com/pytorch/pytorch/blob/152383b74540785da418611a8ae8a7c5028a0cdc/torch/distributed/pipelining/schedules.py#L573C9-L573C26) or [stages](https://github.com/pytorch/pytorch/blob/152383b74540785da418611a8ae8a7c5028a0cdc/torch/distributed/pipelining/schedules.py#L1454).
- Since _has_backwards is False, stage._prepare_backward_infra() will not be called.
- When running the first training step, initialization will not be run again (e.g. [here](https://github.com/pytorch/pytorch/blob/152383b74540785da418611a8ae8a7c5028a0cdc/torch/distributed/pipelining/schedules.py#L1578)).
- Thus, an error occurs when the backwards step is reached.

### Versions

PyTorch 2.9 Nightly
