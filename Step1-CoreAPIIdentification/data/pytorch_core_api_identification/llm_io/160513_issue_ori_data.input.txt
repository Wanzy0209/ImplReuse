Bug Report:
Title: Forward autodiff : Multiplying by python float changes the dual dtype in some situations
Issue ID: 160513
Original bug description: Hello !
This bug report is based on a discussion from the pytorch forum : [https://discuss.pytorch.org/t/forward-autodiff-multiplying-by-python-float-changes-the-dual-dtype-in-some-situations/222163]

## Bug Description
When using `torch.func.jacfwd` (forward-mode automatic differentiation) on a 0‑dimensional dual tensor multiplied by a Python float literal (e.g., `0.5 * x[0]`), the primal retains its declared dtype (e.g. `float32`), but the tangent component is unexpectedly promoted to `float64`. This mismatch causes runtime errors in subsequent tensor operations requiring consistent dtypes, like `torch.tensordot` even though there is no dtype mismatch without autodiff.

## Minimal Repro Example

```python
import torch
print(torch.version.__version__)

fargs = {'dtype': torch.float32, 'device': 'cuda'}
A = torch.rand((5, 3, 100), **fargs)

def test(x):
    a = 0.5 * x[0]
    p, t = torch.autograd.forward_ad.unpack_dual(a)
    print(f"a dtype : {p.dtype}, a.tangent dtype : {t.dtype}")
    v = torch.stack([a, *x[1:]])
    p, t = torch.autograd.forward_ad.unpack_dual(v)
    print(f"v dtype : {p.dtype}, v.tangent dtype : {t.dtype}")
    return torch.tensordot(v, A, dims=1)

torch.func.jacfwd(test)(torch.rand(5, **fargs))
```

## K. Frank’s Diagnostic Example (Clarifying Scope of Bug)

```python
import torch
print(torch.__version__)

primal1d = torch.ones(1)
tangent1d = torch.ones(1)
primal0d = torch.ones(1)[0]
tangent0d = torch.ones(1)[0]

with torch.autograd.forward_ad.dual_level():
    # 1‑D tensor, no scalar multiplication — ok
    dual1d = torch.autograd.forward_ad.make_dual(primal1d, tangent1d)
    p1d, t1d = torch.autograd.forward_ad.unpack_dual(dual1d)
    print(p1d.dtype, t1d.dtype, t1d.dtype == p1d.dtype)

    # 1‑D tensor × Python scalar — still ok
    dual1db = 1.0 * dual1d
    p1db, t1db = torch.autograd.forward_ad.unpack_dual(dual1db)
    print(p1db.dtype, t1db.dtype, t1db.dtype == p1db.dtype)

    # 0‑D tensor, no scalar multiplication — ok
    dual0d = torch.autograd.forward_ad.make_dual(primal0d, tangent0d)
    p0d, t0d = torch.autograd.forward_ad.unpack_dual(dual0d)
    print(p0d.dtype, t0d.dtype, t0d.dtype == p0d.dtype)

    # 0‑D tensor × Python scalar — **BUG**: tangent gets promoted
    dual0db = 1.0 * dual0d
    p0db, t0db = torch.autograd.forward_ad.unpack_dual(dual0db)
    print(p0db.dtype, t0db.dtype, t0db.dtype == p0db.dtype)
```

**Output summary:**

- **1‑D tensor (no scalar)**: primal/tangent both `float32` → OK  
- **1‑D tensor × Python float**: both still `float32` → OK  
- **0‑D tensor (no scalar)**: both `float32` → OK  
- **0‑D tensor × Python float**: primal = `float32`, tangent = **`float64`** → **BUG**

## Workarounds

- Use a tensor when scaling:  
  ```python
  a = torch.tensor(0.5, **fargs) * x[0]
  ```
- Or apply the scalar before slicing:  
  ```python
  a = (0.5 * x)[0]
  ```
Both preserve matching primal and tangent dtypes (`float32`) and avoid the bug.

**Maybe torch can raise a warning if primal and dual values have different dtype during forward autodiff to help debugging ?**
