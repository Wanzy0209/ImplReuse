## Incident timeline (all times pacific)
Failing since July 13

## User impact
The benchmark tracks performance regressions for various operators on cpu.

## Root cause
The baseline values in `expected_ci_operator_benchmark_eager_float32_cpu.csv` needs to be updated everytime there's an improvement. 

## Mitigation
The job should only result in error if there's a performance regression. In case of performance improvement, the task should just keep on running as is. Also, the current regression tracking is comparing the metrics with stored baseline, but the ideal process should generate number based on continuous data

## Prevention/followups

- The process should only fail incase of regressions, while keep on running smoothly in case of performance improvements.
- There needs to be a dedicated oncall and ownership for any failure mitigation in future.
