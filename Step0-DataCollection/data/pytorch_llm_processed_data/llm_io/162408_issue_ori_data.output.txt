**Title**: [bug] torch.cumsum incorrect results on int32 input tensors

**Issue ID**: 162408

**Bug Description**: When the default dtype is bfloat16, torch.cumsum() produces incorrect results on input tensors with dtype int32. The issue happens on both CPU and CUDA devices, but does not happen when torch.set_default_dtype is commented out.

**Repro Code**:
```python
import torch

torch.set_default_dtype(torch.bfloat16)
device = "cpu"
# device="cuda"
seqlens = torch.tensor([434,  78, 101, 411], device=device, dtype=torch.int32)
cu_seqlens = torch.cat((torch.zeros(1, device=device), torch.cumsum(seqlens, dim=0))).to(dtype=torch.int32, device=device)

# Ground truth answer: [   0,  434,  512,  613, 1024]
print(f"{cu_seqlens=}")
```

**Repro Output**:
```
cu_seqlens=tensor([   0,  434,  512,  612, 1024], dtype=torch.int32)
```

**Trigger Conditions**:
- backend: CPU and CUDA
- dtype: int32 (input tensor), bfloat16 (default dtype)
- input_shape: Not specified beyond the example values
- other_conditions: torch.set_default_dtype(torch.bfloat16) must be set

**Affected API**: torch.cumsum

**Environment**:
- pytorch_version: 2.8.0a0+git51cb226
- python_version: 3.10.14
- os: CentOS Stream 9 (x86_64)
- hardware: Intel(R) Xeon(R) Platinum 8480C, NVIDIA H100 80GB HBM3
