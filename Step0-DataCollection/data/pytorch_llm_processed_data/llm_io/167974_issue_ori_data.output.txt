**Title**: EmbeddingBag sum has incorrect offsets when input is 2D and include_last_offset is set to True.

**Issue ID**: 167974

**Bug Description**: The issue describes that when `include_last_offset` is True in EmbeddingBag, the documentation states that "offsets has one additional element, where the last element is equivalent to the size of indices." However, when input indices are 2D, the offsets are generated automatically and don't take into account the `include_last_offset` flag. The generated offsets are [0, 4] instead of the expected [0, 4, 8].

**Repro Code**:
```python
import torch
embedding_sum = torch.nn.EmbeddingBag(10, 3, mode='sum', include_last_offset=True)
input = torch.tensor([[1, 2, 4, 5], [4, 3, 2, 9]], dtype=torch.long)
embedding_sum(input)
```

**Repro Output**: The offsets generated are [0, 4] instead of the expected [0, 4, 8].

- input_shape: 2D input (explicitly mentioned)
