**Title**: all_gather can change memory ordering of tensor

**Issue ID**: 163483

**Bug Description**: The user reports that when using `all_gather` operation on a tensor with `channels_last` format, the memory ordering of the output changes, causing the output and input to not be aligned. The user considers this a bug.

**Reproducible Code**:
```python
import torch

torch.distributed.init_process_group(backend='nccl')
rank = torch.distributed.get_rank()
world_size = torch.distributed.get_world_size()
torch.cuda.set_device(rank)

x = torch.arange(0, 16).reshape(2, 2, 2, 2).cuda().to(memory_format=torch.channels_last)
x_list = [torch.zeros_like(x) for _ in range(world_size)]
torch.distributed.all_gather(x_list, x)

print('rank_{}: {}\n x:\n{}\n gathered_x:\n{}\n'.format(rank, torch.equal(x, x_list[rank]), x.storage(), x_list[rank].storage()))
```

**Repro Output**: The output shows that `torch.equal(x, x_list[rank])` returns `False`, and the storage of `x` and `gathered_x` (x_list[rank]) have different memory ordering:
- x storage: 0, 4, 1, 5, 2, 6, 3, 7, 8, 12, 9, 13, 10, 14, 11, 15
- gathered_x storage: 0, 2, 4, 6, 1, 3, 5, 7, 8, 10, 12, 14, 9, 11, 13, 15

**Trigger Conditions**:
- backend: nccl
- dtype: int64 (from the storage output)
- input_shape: (2, 2, 2, 2)


- other_conditions: Using channels_last memory format

**Affected API**: torch.distributed.all_gather

**Environment**:
