From the issue, I can extract:

1. **title**: "Bug: torch.distributed.pipelining produces incorrect graph when model contains nn.Embedding"

2. **error_description**: The bug description states that when splitting a model containing an nn.Embedding layer into pipeline stages with torch.distributed.pipelining.pipeline API, the pipeline representation incorrectly calls the embedding layer twice. The second call passes the embedding output (a FloatTensor) as the index argument to nn.Embedding, but nn.Embedding expects an index tensor of type LongTensor. This causes an assertion failure with "Tensor dtype mismatch! Expected: Float, Got: long long" error.

3. **repro_code**: The issue provides a complete reproducible script:
```python
import torch
from torch.distributed.pipelining import pipeline, SplitPoint

class X(torch.nn.Module):
    def forward(self, hidden_states):
        return hidden_states.to(torch.float32)

class Y(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.embed_tokens = torch.nn.Embedding(32, 16, -1)
        self.layers = torch.nn.ModuleList([X() for _ in range(2)])

    def forward(self, input_ids):
        x = self.embed_tokens(input_ids)
        _dummy_tensor = torch.zeros(2, 1, 32, 32)
        for layer in self.layers:
            x = layer(x)
        return x

def main():
    model = Y()
    # split before the second layer
    split_point = "layers.1"
    example_input_ids = torch.randint(0, 32, (2, 32), dtype=torch.long)
    print("--- Splitting model into pipeline stages ---")
    try:
        pipe = pipeline(
            model,
            mb_args=(example_input_ids,),
            split_spec={split_point: SplitPoint.BEGINNING},
        )
        print("\n--- Running pipeline ---")
        _output = pipe(example_input_ids)
        print("\n--- Execution successful (bug not reproduced) ---")
    except Exception as e:
        print("\n--- ERROR (bug reproduced) ---")
        print(f"Error message: {e}")

if __name__ == "__main__":
    main()
```
