When creating a MultiplicativeLR scheduler with last_epoch >= 0, PyTorch raises a KeyError because 'initial_lr' is not present in optimizer.param_groups. The scheduler fails even though the optimizer has a valid 'lr'. This appears to be a bug in the scheduler API: it does not automatically populate 'initial_lr' as expected.
import torch
from torch.optim import SGD
from torch.optim.lr_scheduler import MultiplicativeLR

def lr_lambda(epoch):
    return 0.95 ** epoch

model = torch.nn.Linear(10, 2)
optimizer = SGD(model.parameters(), lr=0.1)

# Trigger the bug: last_epoch >= 0
scheduler = MultiplicativeLR(optimizer, lr_lambda=lr_lambda, last_epoch=1)


### Versions

KeyError: "param 'initial_lr' is not specified in param_groups[0] when resuming an optimizer"
This behavior occurs in PyTorch 2.x (tested on multiple versions).
urrent workaround: manually set 'initial_lr' for each param_group
for g in optimizer.param_groups:
    g.setdefault('initial_lr', g['lr'])
