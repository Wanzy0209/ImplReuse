**Title**: No error raised despite shape mismatch in load_state_dict

**Issue ID**: 165873

**Bug Description**: The user reports that when initializing a Parameter of a Module to be a scalar, and then loading a state_dict containing a 1D tensor, no error is raised. Instead, the Parameter takes on the first value of the 1D tensor. The user expects a RuntimeError in this scenario. They note that other combinations (initializing the parameter to be a size [1] 1D tensor, or loading in tensors of 2 or more dimensions) do raise a RuntimeError.

**Repro Code**:
```python
import torch
import torch.nn as nn


class SimpleModule(nn.Module):
    def __init__(self, threshold_value):
        super().__init__()
        self.threshold = nn.Parameter(torch.tensor(threshold_value))
    
    def forward(self, x):
        return x

large_tensor = torch.randn(32000)
state_dict = {"threshold": large_tensor}

module = SimpleModule(0.0)
module.load_state_dict(state_dict)
assert module.threshold.item() == state_dict['threshold'][0].item() 
```

**Repro Output**: The assertion passes, meaning the scalar parameter takes the first value of the 1D tensor without error.

**Trigger Conditions**:
- Backend: Not explicitly specified, but mentions macOS and CUDA
- dtype: Not specified
- input_shape: Scalar parameter being loaded with 1D tensor
- other_conditions: The bug occurs when a scalar parameter is loaded with a 1D tensor

**Affected API**: `load_state_dict` method of `nn.Module`

**Environment**:
- PyTorch version: 2.8.0
- Python version: 3.13.7
- OS: macOS 15.6.1 (arm64)
- Hardware: Apple M3


- Additional context: The issue has been confirmed on CUDA and PyTorch 2.9, with a forum discussion providing further verification.
