**Title**: Bottleneck in _find_nd_overlapping_shards when validating sharded tensors at scale.

**Issue ID**: 166941

**Bug Description**: The `validate_non_overlapping_shards_metadata` function in `torch/distributed/_shard/sharding_spec/_internals.py` has an O(n²) time complexity that causes severe performance degradation at scale. For models with large grid-sharded tensors (e.g., LLaMA-405B with 32×32 sharding = 1024 shards per tensor), this validation adds high overhead (~1 min and 12-20 sec) during distributed setup.

The root cause is the `_find_nd_overlapping_shards` helper function, which uses a nested loop to check all pairs.

**Reproduction Code**: There's a complete Python script provided that creates shards and validates them.

**Repro Output**: Takes ~1min 15+ seconds for 1024 tensors with 1024 shards each.

- Backend: Not explicitly mentioned, but the code uses distributed sharding

**Affected API**: `validate_non_overlapping_shards_metadata` function in `torch/distributed/_shard/sharding_spec/_internals.py`, specifically the `_find_nd_overlapping_shards` helper function.
