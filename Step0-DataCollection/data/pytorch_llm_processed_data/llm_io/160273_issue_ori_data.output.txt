**Title**: [Documentation Clarity] torch.min/torch.max gradient behavior

**Issue ID**: 160273

**Bug Description**: The issue is about documentation clarity regarding the gradient behavior of `torch.min` and `torch.max`. The documentation doesn't mention gradient behavior, while `torch.amin` and `torch.amax` do mention it. However, the user found that the documented behavior for `amin`/`amax` doesn't match the actual behavior of `torch.min` in all cases.

The user demonstrates that:
1. `torch.min` (reduce over all dimensions) distributes gradients evenly (like `amin`)
2. `torch.min(input, dim=...)` (reduce over specified dimension) propagates gradient only to the indexed element (like indexing)

**Repro Code**:
```python
>>> # torch.min -> reduce over all dimensions
>>> a = torch.ones([5]).cuda()
>>> a.requires_grad=True
>>> min_val = torch.min(a)
>>> min_val.backward()
>>> a.grad
tensor([0.2000, 0.2000, 0.2000, 0.2000, 0.2000], device='cuda:0')
...
>>> # torch.min(input, dim=...) -> reduce over specified dimension
>>> a = torch.ones([5]).cuda()
>>> a.requires_grad=True
>>> min_val = torch.min(a, dim=0)
>>> min_val.values.backward()
>>> a.grad
tensor([1., 0., 0., 0., 0.], device='cuda:0')
```

**Repro Output**:
- For `torch.min(a)`: `tensor([0.2000, 0.2000, 0.2000, 0.2000, 0.2000], device='cuda:0')`
- For `torch.min(a, dim=0)`: `tensor([1., 0., 0., 0., 0.], device='cuda:0')`
