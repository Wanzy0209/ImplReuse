# Problem
https://github.com/pytorch/pytorch/commit/398fdd32bbf7b5f8a2b67e637c8a2e46572d9f28 added support for selecting whether a node will fall back to extern kernels on a per-node basis. This was previously supported on a per-target basis via `make_fallback`, but some use cases require configuring fallbacks based on the properties of an individual FX node, as opposed to the target operation.

Extern fallbacks often come with layout constraints. For example, custom operators may be written to only accept one specific memory layout. This is especially common on non-GPU hardware accelerators.

Layout constraints are configurable per target by modifying this [dict](https://github.com/pytorch/pytorch/blob/main/torch/_inductor/lowering.py#L116). However, that mechanism doesn't support finer-grained decisions like applying different layout constraints to a node based on whether it falls back.

# Proposal
Similar to https://github.com/pytorch/pytorch/commit/398fdd32bbf7b5f8a2b67e637c8a2e46572d9f28 , we could add metadata that instructs Inductor to apply a specific layout constraint at the node level, as opposed to the operator level.
