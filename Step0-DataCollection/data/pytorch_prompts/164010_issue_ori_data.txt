There are a few rough edges in `.ci/docker/requirements-docs.txt` (which `docs/requirements.txt` is a symlink of):
1. `pip install -r docs/requirements.txt` pulls `numpy 2.x`, which is incompatible with the pinned versions of `matplotlib` and `tensorboard`.
2. The pinned `matplotlib` versions mean it's *only* possible to install these requirements on Python 3.9/3.10:
```
matplotlib==3.5.3 ; python_version < "3.13"
matplotlib==3.6.3 ; python_version >= "3.13"
```
because matplotlib 3.5.3 only supports Python <=3.10, and matplotlib 3.6.3 only supports Python <=3.11.

I imagine there are some historical constraints I may not be aware of.
- If we *can't* upgrade the pinned `matplotlib` and `tensorboard` versions, we should at least pin `numpy<2` and make sure the library versions we're pinning are compatible with the Python versions they're pinned for.
- If we *can* upgrade `matplotlib` and `tensorboard`, we'd ideally upgrade to versions which support `numpy>2`, obviating the issue and possibly enabling the use of a single environment for development and building the docs.

Perhaps this should be a separate issue, but we should also update the dependencies in `tools/nightly.py`. At a glance, it's missing `expecttest` (causes errors while running tests). It includes `sphinx`, which makes me think it's intended to work for building the docs - but if that's true, it's missing other dependencies it'd need like `matplotlib`.

Also see #163789 - opening this as a separate issue as per @janeyx99's suggestion.

```bash
python3.10 -m venv
source venv/bin/activate
pip install -r docs/requirements.txt
python -c "import matplotlib.pyplot"  # fails with ImportError
```
