Issue ID: 165297
Title: [BUG] MaxPool2d with channels_last + bfloat16 on CUDA produces NaNs for large tensors
Bug Description:
### 🐛 Describe the bug

# Description
When using torch.nn.MaxPool2d on large tensors with memory_format=torch.channels_last on GPU, the output can contain NaN values or even cause an illegal memory access error, depending on dtype and the memory content. This happens even when the input has no NaN/Inf. Changing to contiguous (NCHW) memory format before MaxPool fixes the issue.

# Steps to Reproduce
```python
import torch
import torch.nn as nn

device = torch.device("cuda")

def test_maxpool_nan():
    # Large input tensor
    N, C, H, W = 84, 64, 512, 960
    # Case 1: bfloat16 + channels_last  => NaN
    x = torch.randn(N, C, H, W, dtype=torch.bfloat16, device=device)

    # Case 2: float32 + channels_last => illegal memory access
    # x = torch.randn(N, C, H, W, device=device)  # default float32


    # Convert to NHWC channels_last layout
    x = x.to(memory_format=torch.channels_last)

    # Uncommenting the line below avoids NaNs
    # x = x.contiguous()

    print(f"Input tensor: contiguous={x.is_contiguous()}, channels_last={x.is_contiguous(memory_format=torch.channels_last)}")
    print(f"Input stride: {x.stride()}")

    pool = nn.MaxPool2d(kernel_size=3, stride=2, padding=1).to(device)
