Issue ID: 165873
Title: No error raised despite shape mismatch in load_state_dict
Bug Description:
### 🐛 Describe the bug

When I initialize a Parameter of a Module to be a scalar, and then load in a state_dict containing a 1D tensor, there is no error; instead, the Parameter takes on the first value of the 1D tensor without complaint. In this scenario, I would expect there to be a RuntimeError. Indeed, if you you try other combinations (initializing the parameter to be a size [1] 1D tensor, or loading in tensors of 2 or more dimensions), a RuntimeError is raised.

See the following code for an example; the assertion passes:

```python
import torch
import torch.nn as nn


class SimpleModule(nn.Module):
    def __init__(self, threshold_value):
        super().__init__()
        self.threshold = nn.Parameter(torch.tensor(threshold_value))
    
    def forward(self, x):
        return x

large_tensor = torch.randn(32000)
state_dict = {"threshold": large_tensor}

module = SimpleModule(0.0)
module.load_state_dict(state_dict)
assert module.threshold.item() == state_dict['threshold'][0].item() 
```

I tested this on version 2.8 on macOS, but this error occurs on CUDA too. Also see [this short thread](https://discuss.pytorch.org/t/no-error-raised-despite-shape-mismatch-in-load-state-dict/223641/2) where another forumgoer, KFrank, confirms that this occurs in 2.9 and did some more testing of when this bug occurs.
