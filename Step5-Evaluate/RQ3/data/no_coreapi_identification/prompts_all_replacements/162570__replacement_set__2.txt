Issue ID: 162570
Title: ONNX export of atan2 produces different result thantorch.atan2when input is zero
Bug Description:
### 🐛 Describe the bug

`torch.atan2(x, y)` returns zero when both inputs are zero. The ONNX [decomposition of atan2](https://github.com/pytorch/pytorch/blob/1c16c18a534d320d101ebb10c88bdf57cf84b3b1/torch/onnx/_internal/torchscript_exporter/symbolic_opset9.py#L739) produces NaN in this case. This issue also affects `torch.angle` which decomposes to `torch.atan2(x.imag, x.real)`. 

I encountered this issue when debugging an issue with an ONNX export of the Kokoro TTS model ([original issue](https://github.com/robertknight/rten/pull/928#issuecomment-3273328165)).

**Reproduction:**

```py
import onnxruntime as ort
import torch
import torch.nn as nn


class Net(nn.Module):
    def forward(self, x, y):
        return torch.atan2(x, y)


net = Net()
x = torch.tensor([0.0])
y = torch.tensor([0.0])
torch.onnx.export(
    net, (x, y), "atan2.onnx", input_names=["x", "y"], output_names=["output"]
)

sess = ort.InferenceSession("atan2.onnx")

torch_result = net(x, y)
ort_result = sess.run(["output"], {"x": x.numpy(), "y": y.numpy()})[0]

print("torch_result", torch_result) # tensor([0.])
print("ort_result", ort_result) # [nan]
```
