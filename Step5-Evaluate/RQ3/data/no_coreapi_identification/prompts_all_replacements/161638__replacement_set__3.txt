Issue ID: 161638
Title: Nan gradients when using logsumexp
Bug Description:
### 🐛 Describe the bug

When applying logsumexp over a particular dimension, non-finite values can result in `nan` gradients even if they do not contribute to the final scalar on which `.backward` is called. I cannot see a reason for why this ought to be the expected behaviour. Sorry if it is.

```python
import torch


x = torch.tensor([[1., 2., -torch.inf], [2., 1., -torch.inf]])
t = torch.tensor(1., dtype=torch.float32, requires_grad=True)
y = torch.logsumexp(x / t, dim=0)
print(f"{y=}")

z = y[y.isfinite()].mean() # All non-finite values excluded in the calculation of z
z.backward()
print(f"{t.grad=}")

t.grad = None
y2 = torch.logsumexp(x[:, :2] / t, dim=0) # If non-finite values are excluded before logsumexp, all works fine
print(f"{y2=}")
z2 = y2[y2.isfinite()].mean()
z2.backward()
print(f"{t.grad=}")
```

Results in

```
y=tensor([2.3133, 2.3133,   -inf], grad_fn=<LogsumexpBackward0>)
t.grad=tensor(nan)
y2=tensor([2.3133, 2.3133], grad_fn=<LogsumexpBackward0>)
t.grad=tensor(-1.7311)
```
