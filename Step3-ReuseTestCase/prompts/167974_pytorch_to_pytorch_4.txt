Issue ID: 167974
Title: EmbeddingBag sum has incorrect offsets when input is 2D and include_last_offset is set to True.
Bug Description:
### 🐛 Describe the bug

According to the documentation, when the parameter include_last_offset is True, it is expected that “offsets has one additional element, where the last element is equivalent to the size of indices.” However, when the input indices are 2D, the offsets are generated automatically by the framework and it does not take into account the include_last_offset flag. As a result, the generated offsets are, in my opinion, incorrect.
Place where offsets are generated in that case: https://github.com/pytorch/pytorch/blob/99117c1238c9adcd3fb2621e36c91f9d20ed2ff7/torch/nn/functional.py#L2724-L2726

Repro script:
```python
import torch
embedding_sum = torch.nn.EmbeddingBag(10, 3, mode='sum', include_last_offset=True)
input = torch.tensor([[1, 2, 4, 5], [4, 3, 2, 9]], dtype=torch.long)
embedding_sum(input)
```

By modifying functional.py, I managed to collect the offsets that are generated; in this case they are: [0, 4]
instead of the expected: [0, 4, 8].

If my reasoning is correct and this is in fact an issue, it can be easily fixed by appending to the offsets the size of indices when include_last_offset is True.
Another idea could be to ignore the include_last_offset flag when the input is 2D, but this would require updates to the documentation and the code.
