Issue ID: 163372
Title: Expand sometimes interpreted as Repeat by compiler
Bug Description:
### 🐛 Describe the bug

This sample code leads to a huge amount or RAM allocated on GPU.
It seems like torch.expand() is interpreted as torch.repeat(), leading the compiled code to try to allocate much more memory than needed instead of seeing it as a View.

Versions to reproduce:
* It works when NOT compiled with torch 2.5.1 / 2.7.1 / 2.8.0
* It works when compiled with torch 2.5.1
* It doesn't work (=huge RAM allocated) when compiled with torch 2.7.1 / 2.8.0

Ablation:
* It only fails with the Inductor backend
* It fails with all 3 modes (default/reduce-overhead/max-autotune)

```
import torch

BATCH_SIZE = 64
CHANNELS, IMG_SIZE = 3, 224
GRID_SIZE = 13

class MyModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.grid = torch.nn.Parameter(torch.randn((5000, GRID_SIZE, GRID_SIZE, 2), device='cuda'))
        self.fc = torch.nn.Linear(GRID_SIZE*GRID_SIZE*CHANNELS, 16)

    def forward(self, x):
        per_channel = []
        for i in range(CHANNELS):
            channel = x[:,i,...].expand(5000,-1,-1,-1)
            patch = torch.nn.functional.grid_sample(channel, self.grid, mode="bilinear", align_corners=False, padding_mode="border")
            patch = patch.transpose(0,1).flatten(start_dim=2)
            per_channel.append(patch)
        x = torch.cat(per_channel, axis=2)
        x = self.fc(x)
        return x

def main():
    model = MyModel()
