Issue ID: 161905
Title: [MPS]torch.compileResNet-18 model fails duringloss.backward()on MPS backend, but works on CPU
Bug Description:
### 🐛 Describe the bug

#### 🐛 Bug

When using `torch.compile` on a model that has been moved to the `mps` device on macOS, calling `loss.backward()` results in a runtime error. The forward pass completes without issues.

Notably, the exact same code runs successfully without any errors when the model and data are on the `cpu` backend. This suggests a potential bug or unimplemented feature in the `torch.compile` support for the MPS backend, specifically concerning the backward pass (gradient computation).
