Issue ID: 165549
Title: Operations likeabs(dispatched via CompositeExplicitAutograd) return empty tensors when run through cpu_fallback
Bug Description:
### 🐛 Describe the bug

When a custom device backend relies on CPU fallback for unimplemented operations, `CompositeExplicitAutograd` operations fail to return properly sized tensors. This affects operations like `abs`, `isfinite`, `isinf`, and `isnan`.

assuming we have implemented the minimal set of ops as described: https://docs.pytorch.org/docs/main/accelerator/operators.html for a privateuse1 out-of-tree backend, and implementing the cpu fallback as described (just a call to `at::native::cpu_fallback(op, stack);`)

```python
# This fails - returns tensor with shape [0]
t = torch.randn(4, 4, device='privateuse1')
result = torch.abs(t)  # result.shape == torch.Size([0])

# But these work correctly
torch.abs(t, out=pre_allocated_tensor)  # Works
t.abs_()  # Works (in-place)
torch.neg(t)  # Works (uses structured_delegate)
```
