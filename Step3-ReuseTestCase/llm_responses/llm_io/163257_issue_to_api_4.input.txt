Issue ID: 163257
Title: Support checkPoolLiveAllocations with pluggable device
Bug Description:
### 🚀 The feature, motivation and pitch

# Summary 

Pytorch currently supports using separate device allocators via `torch.cuda.memory.change_memory_allocator`.  However, this breaks torch compile functionality:

```
RuntimeError: pluggable does not yet support checkPoolLiveAllocations. If you need it, please file an issue describing your use case.
```

I'd like to request pytorch support `checkPoolLiveAllocations` when using non-standard memory pool allocators.

## Use Case

I am doing performance optimizations for a neural operator network with a complicated preprocessing pipeline.  For optimal performance, and memory management, it's critical to share the memory pool between pytorch and rapids, via the rapids memory manager:

```python
    import rmm
    from rmm.allocators.torch import rmm_torch_allocator
    import torch

    rmm.reinitialize(pool_allocator=True)
    torch.cuda.memory.change_current_allocator(rmm_torch_allocator)
```

The preprocessing pipeline needs to compute a kNN operation, and the `cuml` kNN is the most performant for this workload.

On the other hand, on H100 the model itself has relatively small kernels and gpu utilization is poor: the GPU is finishing nearly every kernel before the next one can launch.  This would straightforward to improve with cuda graphs and triton fusions via `torch.compile`, however, the changed memory allocator and end-to-end model compilation are incompatible.
